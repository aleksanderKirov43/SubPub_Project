# SubPub Project

## 🚀 Описание сервиса
📌 Сервис Pub/Sub реализует шину событий, работающую по принципу Publisher-Subscriber. 

- Подписчики могут подписываться на события по `subject`.
- Отправители публикуют события, и все подписчики получают их. 
- Используется gRPC для связи между клиентом и сервером. 
- **REST-API** позволяет отправлять запросы через **HTTP.** (Реализовал для тестирования через **Postman**)

📌 Сервис поддерживает: 

- **gRPC и REST** → подписка и публикация событий через два протокола. 
- Конфигурацию **(config.yaml)** → настраиваем порты. 
- Логирование **(log.Println())** → сервис пишет ключевые события в консоль. 
- Автоматическое тестирование **(go test ./...)** → гарантирует стабильность сервиса. 
- **CI/CD** через **GitHub Actions** → обеспечивает проверку качества кода.

## 🔧 Установка и сборка

### 1️⃣ Клонирование репозитория
```sh
git clone https://github.com/yourrepo.git
cd SubPub_Project
go mod tidy
```
### 2️⃣ Запуск сервера
```sh
go run cmd/server/main.go
```
После этого он будет доступен: 
- gRPC → localhost:8082 
- REST → http://localhost:8081

📌 2. Запросы к сервису

📌 Отправка события (Publish). Отправляем запрос на публикацию события:
```sh
curl -X POST http://localhost:8081/v1/pubsub/publish \
     -H "Content-Type: application/json" \
     -d '{"key": "test-key", "data": "Hello, world!"}'
```
**Ответ:** {} (успешно отправлено)

___

📌 Отправляем POST-запрос на публикацию события: 
- Адрес: http://localhost:8081/v1/pubsub/publish 
- Тело запроса (JSON):
```JSON
{
  "key": "test-key",
  "data": "Hello, world!"
}
```
📌 Если публикация прошла успешно, сервер ответит пустым JSON:  
- Статус: 200 OK  
- Тело ответа: { }

📌 В процессе разработки релизовано **несколько архитектурных паттернов:**

✅ **Dependency Injection (DI)**  
- Передаю зависимости (`subpub`) в `app.NewServer()`, вместо создания их внутри, что улучшает тестируемость и гибкость кода.

✅ **Graceful Shutdown**  
- В `Close(ctx context.Context)` используется контекст. Если `ctx` отменён, система корректно завершает работу, не ломая подписчиков.

✅ **CQRS (Command-Query Responsibility Segregation)**  
- **`Subscribe()` и `Publish()` разделяют функционал** (запрос и команда). Это делает API понятным и более устойчивым к изменениям.
